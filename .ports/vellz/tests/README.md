# Tests and fixtures

## Scene corpus

`tests/scenes/*.json` is the single source of truth for differential tests.
The same files are rendered by:

- the upstream oracle (`tools/oracle-rs`, pinned `vello_cpu`), and
- vellz (the Zig CLI, once the corresponding feature is implemented).

Scene construction, transforms, colors, and settings therefore cannot drift
between the two implementations.

## Fixtures

`tests/fixtures/oracle/` contains, per scene:

- `<name>.rgba` — raw premultiplied sRGB RGBA8 pixels (exact comparison),
- `<name>.json` — metadata written by the oracle: dimensions, pipeline
  settings, pinned revision, and FNV-1a hashes of scene and output,
- `<name>.png` — optional human-readable preview (never used for comparison).

Fixtures are generated by the pinned upstream revision:

```sh
tools/fetch-reference.sh
cd .reference/vello && cargo build --release -p vello_toy && cd ../..
tools/render_corpus.sh --png          # regenerate + double-render determinism check
tools/render_corpus.sh --check        # verify committed fixtures without writing
```

Provenance: the scenes are original to this repository; the oracle outputs are
produced by code from <https://github.com/linebender/vello> at
`1e63b4a40ccb484f82e1d85b83df97ab95bcfbe83` (Apache-2.0 OR MIT). Upstream test
assets later imported as fixtures keep their own license files alongside them.

## Comparison policy

`tools/compare.py` reports exact mismatches, per-channel statistics, and a diff
image. The default is exact equality. A tolerance is allowed only when a
documented algorithmic difference exists (for example a different SIMD
reduction order) and must state:

- the fixture and the compared backends,
- the metric and threshold,
- why exact equality is not achievable.

Tolerances never mask missing geometry: a scene whose feature is unimplemented
must fail loudly or be absent from the corpus, not produce approximate output.
